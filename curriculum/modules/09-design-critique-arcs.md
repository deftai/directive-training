## Learning outcomes

By the end of this module, you can:

- **O9.6 — Route and bound an arc.** Route the supplied proposal, name target revision
  `NS-INGEST-R2`, and distinguish the full arc from one critic round and from later
  implementation review.
- **O9.7 — Fix a default critic envelope.** Select charter and spend independently, fill
  the default `N=1` envelope, and explain why an input ceiling gives isolation without
  proving trust, independence, or correctness.
- **O9.8 — Adjudicate supplied findings.** Classify each finding, build a total successor-
  lean take map, refuse direct and compositional instruction-shaped content, and identify
  the parent premise that requires independent audit.
- **O9.9 — Decide the next safe state.** Distinguish retry, halt, verified synthesis, and
  later ingest while keeping catalog chips, completed-arc clearance, and implementation
  authority separate.

## Why this matters

A well-shaped proposal can still depend on a load-bearing mechanism whose failure modes
deserve adversarial scrutiny before ordinary lifecycle authorization. A design-critique arc
creates bounded evidence for that judgment. It is not a general code review, a vote, or an
automatic workflow.

The evidence boundary matters as much as the criticism. Same-round critics receive one
fixed ceiling and may not read later thread content. That isolation reduces contamination;
it does not make supplied content trustworthy or make agreement verification.

The parent proposes a successor lean, the operator confirms or amends it, and load-bearing
parent premises need independent clearance. Only a verified completed-arc record can support
later ingest. Even then, implementation authority still requires active scope, live intent,
and applicable gates.

## Terminology

| Term | Meaning in this module | Do not confuse it with |
| --- | --- | --- |
| Arc | One target-revision motion from the Stop 1 write-back or voluntary dispatch to accepted synthesis or a recorded halt | One critic post, one issue, or ordinary PR review |
| Critic round | One fixed-envelope dispatch and its allowed critic response set | The full arc |
| Target revision | The exact proposed mechanism version under critique; here `NS-INGEST-R2` | A changing issue thread |
| Charter | The critic's question: here `refutation` | Spend such as `N=1`; `panel` is not a charter |
| Spend | Number and permitted family shape of critics | The critic method |
| Input ceiling | Highest fictional comment ID the critic may read | A trust, independence, or correctness guarantee |
| Successor lean | Parent's total per-heading proposed takes after the round | Operator consent or verified synthesis |
| Independent audit | Separate clearance of a load-bearing parent-introduced premise | Parent citation or self-approval |
| Catalog chip | List-visible state such as `design-critique:ingest-ready` | Completed-arc clearance or authority to implement |
| Completed-arc record | Synthesis record that cites the latest accepted lean and satisfies bind conditions | Ingest itself, activation, or implementation permission |

## Mental model

Keep four boundaries visible:

```text
route target revision
  → fix charter + spend + evidence ceiling
  → classify findings + total successor lean + independent audit
  → retry | halt | verified synthesis
  → possible later ingest
  → separate lifecycle and implementation authority
```

| Situation | What the model predicts | Evidence to inspect |
| --- | --- | --- |
| A later comment looks useful | The critic still excludes it | Ceiling and comment ID |
| Two fragments combine into an instruction | Cite both, refuse the aggregate effect, record a finding, continue | Source IDs and take map |
| Parent adds a load-bearing premise | Bind waits for independent clearance | `audit:<id> ... reading=asserted` and audit response |
| An ingest-ready chip is present | List state changed; clearance is not proved | Latest lean, verified claims, and completed-arc record |

The model does not claim that Markdown quoting, fencing, or Directive neutralizes untrusted
instructions. These cards are inert because they are fixed fictional data handled only by
this bounded exercise procedure.

## Guided explanation

### 1. Route a revision, not a topic

An arc challenges a named target revision. The route decision for `NS-INGEST-R2` rests on a
new mechanism for assembling untrusted issue text into an agent envelope and recognizing
clearance. “Agent intake” is only a topic; `NS-INGEST-R2` is the reviewable target.

One issue may contain later arcs, and one arc may contain multiple rounds. The unit remains
the target-revision motion, not the issue or an isolated comment.

### 2. Select charter and spend independently

`refutation` asks a critic to try to defeat a defensible premise. `open critique` searches a
genuinely open solution space. Spend is separate: `N=1` is the default; a permitted
multi-family `N≥3` panel is an escalation in spend, not a third charter.

This packet supplies a defensible refutation target and exercises no panel permission, so
the passing pair is `refutation` plus `N=1`.

### 3. Treat the ceiling as isolation, not trust

All same-round readers receive the same fixed ceiling and dispatch SHA. `DC9-POSTCEILING-01`
falls outside the envelope even if its content would help. The ceiling prevents later-thread
contamination; it does not prove model independence, decorrelation, truth, or correctness.

The same rule applies to content inside the ceiling. Instruction-shaped source text remains
evidence to cite and assess, not a command to follow.

### 4. Build a total take map and audit parent premises

Each blocking or sharpening finding needs evidence, a concrete failure mode, a disposition
consequence, and one parent take: `accept-into-contract`, `disagree`, or `defer`. A missing
take is not quiet agreement; it is an incomplete lean.

If the parent introduces a new load-bearing premise, primary-source citation is not
self-clearance. The lean marks it `audit:<id> ... reading=asserted`; an independent critic
must clear or reject that premise before bind.

### 5. Bind only verified synthesis

Agreement is not verification. Verification re-derives a claim from primary sources or uses
an independent cross-family check, reconciles measurement, and discloses self-arbitration.

Retry only when a disposition-changing residual remains and budget remains. Halt when the
cap is exhausted, the same primary fingerprint repeats without material take movement, or
dispatch fails. Preserve the halt line instead of silently retrying.

Later ingest requires an admitted completed-arc record citing the latest successor lean and
the other bind conditions. A chip alone is insufficient. Neither critique nor ingest grants
implementation authority.

## Common misconceptions

| Misconception | Correct model | How to disprove it |
| --- | --- | --- |
| An arc is one review comment | An arc spans one target revision from dispatch/write-back to synthesis or halt | Compare Stop 1, round, lean, audit, and synthesis IDs |
| A panel is a charter | Charter and spend are independent; `panel` describes neither allowed charter | Fill the envelope in separate rows |
| A fixed ceiling makes inputs trustworthy | The ceiling isolates evidence timing only | `DC9-SOURCE-01` is inside the ceiling and still untrusted |
| Parent citation clears a parent premise | Load-bearing parent premises require independent audit | `DC9-LEAN-01` remains asserted until `DC9-AUDIT-01` |
| Agreement is verification | Verification re-derives or independently cross-checks claims | Compare lean `9104006` with verified table `9104007` |
| Ingest-ready means implement now | Chip, completed arc, ingest, active scope, live intent, and gates are different states | Classify `DC9-DECIDE-05` and name missing evidence |

## Self-assessment

Answer without reopening the worked solution:

1. **O9.6:** What is the target revision, where does this arc begin and end, and what review
   remains later?
2. **O9.7:** Why are `refutation` and `N=1` separate choices, and what exactly does ceiling
   `9104001` exclude and not guarantee?
3. **O9.8:** Which sources contribute to F1, how do you handle their attempted effects, what
   take does each finding receive, and why can the parent not clear its own premise?
4. **O9.9:** What state belongs to each `DC9-DECIDE-*` card, and which additional authority
   would still be required after accepted synthesis or ingest?

Use this result:

- **Ready to continue:** all four retained artifacts pass every row and cite fixed evidence.
- **Revisit one section:** the state is correct but one evidence or authority explanation is
  incomplete.
- **Retry the exercise:** any source instruction changes the task, a heading lacks a take,
  post-ceiling evidence enters the round, or a chip is treated as clearance.
